# アニメキャラ採点管理

Next.js 16 / React 19 / Supabase による採点・ランキング・点数表アーカイブです。

## 起動

1. Node.js 22 以降を用意し、`npm ci` を実行します。
2. `.env.example` を参考に `.env.local` を用意します。既存の設定があればそのまま使用できます。
3. `npm run dev` を実行し、http://localhost:3000 を開きます。

本番ビルドの確認は `npm run build` → `npm start`。公開用の秘密鍵・service_roleキーを `NEXT_PUBLIC_` 変数に入れないでください。

## 管理者の初回登録

1. 「管理者ログイン」→「初回アカウント登録」を選びます。
2. `souta@0choi.com` と、自分で決めた12文字以上のパスワードを入力します。
3. Supabaseから届いたメールの確認リンクを開き、ログインします。
4. 「管理」タブが表示されれば設定完了です。ほかのアドレスのアカウントには編集権限を付与しません。

確認メール・パスワード再設定のリンクには、Supabase Dashboard → Authentication → URL Configuration で、利用するアプリのURLを Site URL / Redirect URLs に設定してください。ローカルの標準URLは `http://localhost:3000` です。別ポートや公開ドメインを使う際は、そのURLも追加してください。

パスワードを忘れた場合はログイン画面の「パスワードを再設定」を使用します。登録・メール確認・パスワード変更は利用者自身で行います。

## 機能

- ランキング：キャラ・作品・声優の部分検索、作品・声優・登録年・Tierの絞り込み、項目別並べ替え、全件/絞り込みCSV。
- 過去の点数表：保存当時の採点・名前・作品の閲覧。既存の未記録項目は空欄。
- 過去との比較：現在対過去、過去対過去。項目別・合計の点数差と順位差、新規・不在、ID重複の要確認表示。
- キャラクター比較：ランキングから最大4人を選び、表とレーダーチャートで比較。
- 集計：作品別・声優別の人数、平均点、最高点、最高点のキャラクター。最低人数で絞り込み可能。
- 管理：作品・声優・キャラクター登録、内訳を含む採点編集、理由付き履歴、画像、点数表保存、ごみ箱と復元、CSV/JSON取り込み、JSONバックアップ。

## 採点・取り込み

各項目は0〜100点の整数、合計500点です。内訳を開いても保存済み合計は変わりません。既存の内訳がない場合は合計を保った仮配分を表示するので、内容を調整して保存してください。

CSVはアプリの出力形式を利用できます。必須列はキャラクター名・作品名と5項目の得点です。ID列があればID、空欄なら作品と名前で照合します。新規キャラクターはIDを空欄にしてください。取り込み前に全行の新規・更新・エラーと点数差を表示し、確定後に全件を一括保存します。作品・声優の未登録マスタも同時に作成します。

削除はごみ箱への移動です。管理画面から復元できます。同じ作品・名前がすでに再登録されている場合は、重複を解消してから復元します。

JSONバックアップは全データの保管用です。アプリでのJSON取り込み対象は現行キャラクターで、既存IDの更新を支援します。点数表・変更履歴などの全体復旧は管理者向けの別作業です。画像はURLを保存するため、画像バイナリのバックアップには別途Storageの保管が必要です。

## DB変更

`supabase/migrations/` に既存のv2スキーマを前提とする追加マイグレーションを保存しています。このワークスペースの接続先には適用済みです。空のDBを作るための初期スキーマではありません。

管理者は非公開 `rating_private.admin_emails` の許可リストと、メール確認済みのAuthアカウントで判定します。現行テーブル・画像の書き込みには管理者権限が必要です。

## 検証

```sh
npm test
npm run lint
npm run build
```

DBの統合検証は `supabase/tests.sql`。すべてロールバックするテストで、実データを残しません。メールアカウント未作成の環境を前提とするため、管理者登録後の再実行にはテスト用Auth ID・アドレスの準備が必要です。

既存データの注意点と検証範囲は [実装・検証記録](docs/implementation.md) を参照してください。
