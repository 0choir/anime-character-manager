# 実装・検証記録

## 2026-10-27 の変更

- 現行252人、既存点数表4件・806行を維持。
- `souta@0choi.com` を管理者許可リストへ登録。Supabase Auth のメール確認済みアカウントと照合する。初回登録とメール確認は利用者が画面で行う。
- 管理者判定の固定ID・パスワードと `localStorage` フラグを撤去。
- 作品・声優・キャラクター・採点・点数表・変更履歴と画像アップロードの権限を設定。
- アプリのビューは `security_invoker`。認証情報と許可リストを確認する関数だけ、非公開 `rating_private` スキーマで最小限の `SECURITY DEFINER` を使用。
- キャラクターと採点の一括保存、競合検知、理由付き履歴、論理削除・復元、内訳の永続化、点数表作成、CSV/JSON取り込み、整合性のあるJSONバックアップを追加。
- 順位・称号・Tierは既存の計算式を維持。過去の名前・作品名を現在の値で上書きする表示を修正。新規点数表は順位・称号・Tierも保存する。
- 新規画像には毎回異なるファイル名を付け、過去点数表に保存した画像URLを保持。DB保存に失敗した新規画像は削除を試みる。
- 取得は件数を確認しながら200行ずつ安定した順序で読み込む。ランキング表示は25人ずつ、CSVは選択した表の全件または絞り込み結果全件。
- Google Fontsのビルド時ダウンロードを外し、日本語のシステムフォントを使用。

## 履歴データの既存の不整合

`2024年` と `2026年5月` に、それぞれキャラクターID `352` と `408` の重複行がある。保存点数が異なるため自動統合していない。比較画面は「照合要確認」と表示し、これらのIDの差分を計算しない。点数表の閲覧とCSVには全行を保持する。

過去の登録年・採点内訳など、当時保存されていない値を現在の情報から補完しない。

## 検証

- `npm test`：内訳の合計保持、順位差と点数差の分離、重複ID、絞り込み、集計、CSVの引用符・改行、取り込み照合、JSON形式、日付を検証。
- `supabase/tests.sql`：実DBで管理者・非管理者・未認証を切り替えて検証。保存、制約エラー時の取り消し、競合、点数表、名前保持、画像URL更新、削除と復元、一括取り込み、バックアップ、権限拒否を確認。テスト全体をロールバックし、テストアカウント・採点・点数表を残さない。
- `npm run lint`、`npm run build`。
- 本番サーバーをブラウザで開き、実DBの252人、作品名検索、2人の比較、レーダーチャート、過去比較、声優別集計、過去点数表切り替え、項目順ソート、CSV保存を確認。CSVは252行・全行16列であることを確認。

## DB変更の範囲

このSupabaseプロジェクトは別のプレイリストアプリとも共有されている。今回の変更は現行の採点アプリのテーブル・ビュー・関数と `character-images` バケットへの制御に限定。既存の他バケット向けポリシーの動作は維持する。

Security Advisor には別アプリの `artists` / `albums` / `tracks` / `playlist_records`、旧版の `characters` / `score_histories` と旧ビューなどに既存指摘がある。今回追加・更新した現行アプリのビュー・関数に同種の指摘はない。`rating_private.admin_emails` の「RLS有効・ポリシーなし」は、クライアントから許可リストを直接参照させない意図的な設定。

## バックアップの範囲

JSONには現行・ごみ箱のキャラクター、採点内訳、作品・声優マスタ、全点数表、全変更履歴を同一時点のデータとして含める。画像はURLを保存し、画像バイナリやAuth認証情報は含まない。画像の実ファイルはSupabase Storageに残す。

アプリのJSON取り込みは現行キャラクターの復元・再取り込みに対応。点数表・ごみ箱・変更履歴を含むDB全体の復元は、バックアップJSONを利用した管理者による別の復旧作業になる。
